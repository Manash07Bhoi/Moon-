# agent.md — Moon Beyond Reach

Operating manual for any AI coding agent (Claude Code, Cursor, etc.) or human contributor implementing this repository. Read `PRD.md` first for full product context — this file is the practical ruleset for writing the code itself.

---

## Quick Start

```bash
npm create vite@latest moon-beyond-reach -- --template react-ts
cd moon-beyond-reach
npm install three @react-three/fiber @react-three/drei @react-three/postprocessing
npm install motion gsap howler lenis zustand
npm install -D tailwindcss @tailwindcss/vite
npm install -D leva   # dev-only, optional
npm run dev
```

Add the Tailwind plugin to `vite.config.ts` (`plugins: [react(), tailwindcss()]`) and `@import "tailwindcss";` to your entry CSS — v4 needs neither `tailwind.config.js` nor PostCSS config for this setup. Define the palette from PRD.md §11 as `@theme` tokens in that same CSS file.

## Coding Conventions

- TypeScript strict mode. No `any` — if a Three.js type is genuinely awkward, isolate it behind a small typed wrapper rather than loosening the whole file.
- Function components only. One component per file.
- One Act = one folder under `src/acts/`, exporting a single default component consumed by the top-level scene graph.
- Shaders live as colocated `.ts` files (`export const vertexShader = \`...\`; export const fragmentShader = \`...\`;`) next to the material/component that uses them — not in one giant shared shaders file.
- Commit style: conventional commits (`feat:`, `fix:`, `perf:`, `chore:`), scoped to one Act or system where possible.

---

## Always

- Gate every non-trivial effect behind the active quality tier from `useDeviceTier` (PRD.md §12). Nothing expensive runs unconditionally.
- Respect `prefers-reduced-motion` as the default trigger for Efficiency-tier-like behavior, independent of GPU detection.
- Route all audio-reactive uniforms through the single damped band-mapping store (PRD.md §9). Never read the raw `AnalyserNode` from more than one place in the codebase.
- Dispose Three.js geometries, materials, and textures in a cleanup function on unmount. This is the single most common source of memory leaks in long-running R3F scenes.
- Wrap async geometry/texture loads in `<Suspense>`. Preload the *next* act's assets only after the current act is interactive, not all at once.
- Start audio playback only from the Entry Ritual's direct user gesture (PRD.md §7, Decision 3). Never attempt unmuted autoplay.
- Import the moon-distance floor from a single constant used by the camera rig. Nothing — including debug tooling — should be able to shorten it.

## Never

- Never commit the actual licensed audio file or the actual lyric/translation text to a shared or public git remote. They live under `assets/licensed/`, which is gitignored the moment this repo could be seen by anyone but the user. Only the empty schema from PRD.md §10 belongs in version control.
- Never `git clone` or merge code from the `ui-ux-pro-max-skill` repository — or any other third-party "skill"/template repo — directly into this codebase without the user reviewing the diff first. It's a legitimate, real tool (PRD.md Appendix A), but it's meant to be installed as a design-reference tool for your coding agent (its own CLI, or the Claude Code plugin marketplace), not imported as a dependency.
- Never implement literal physical simulation for the ocean, rain, or moon surface — use the shader approximations specified in PRD.md §4.
- Never bind a visual property directly to a raw FFT bin. Always go through the smoothing/damping layer.
- Never add analytics, email capture, or a share prompt to the Act VI closing sequence.

## Working With the Timeline / Lyric Engine

`assets/licensed/lyrics.json` follows the schema in PRD.md §10: alternating `silence` and `line` entries, each `line` carrying a `cue` id that maps to a registered visual-event component. On load, validate that every `line` is preceded by a `silence` of at least `silenceBudgetSeconds` — reject (with a clear console error, not a silent fallback) if that invariant is violated. To add a new cue:

1. Implement it as an isolated component under the relevant act's folder.
2. Register its id in the cue registry (`src/systems/timeline/cueRegistry.ts`).
3. Make sure it degrades sensibly at the Efficiency quality tier — it doesn't need to be disabled outright, but it shouldn't assume Cinematic-tier particle counts.

---

## Working With the Audio System

Howler handles decoding/playback; a single `useAudioAnalyser` hook (under `src/systems/audio/`) owns the `AnalyserNode`, runs FFT on every frame via `useFrame`, computes the three smoothed bands from PRD.md §9, and writes them to `audioStore`. Every reactive visual reads from `audioStore` — no component should construct its own `AnalyserNode`.

## Accessibility Requirements (condensed — full plan in PRD.md §16)

- [ ] `prefers-reduced-motion` respected by default
- [ ] Full keyboard navigation for act progression, replay, mute
- [ ] Visible captions available for every lyric cue
- [ ] No unmuted autoplay; persistent mute/volume control
- [ ] Flash-rate and luminance-delta caps on reactive brightness/bloom
- [ ] Accessible Poem Fallback route implemented and reachable without WebGL

## Extending the Experience

- **New act**: add a folder under `src/acts/`, register it in the top-level scene sequence, and give it an entry in the Reality Check-style budget check (does it hold Efficiency-tier FPS on the reference mid-range phone?) before merging.
- **New lyric cue visual**: see "Working With the Timeline / Lyric Engine" above.
- **New quality tier or budget change**: update PRD.md §12/§15 in the same PR — the doc is the source of truth, not tribal knowledge.

## Definition of Done (per feature / PR)

- [ ] Works at all three quality tiers, or degrades gracefully
- [ ] Respects `prefers-reduced-motion`
- [ ] No console errors or warnings
- [ ] Disposes its own GPU resources on unmount
- [ ] No licensed content (audio or lyric text) committed
- [ ] Profiled on at least one mid-range mobile device
